# 絵コンテ駆動パイプライン 設計

- 作成日: 2026-08-03
- status: **設計案。未合意・未実装**
- 前提: [06_T4アニメ制作パイプライン検討.md](06_T4アニメ制作パイプライン検討.md) §4、
  実証記録 [08_中割り検証_20260803.md](08_中割り検証_20260803.md)

## 1. 解決する問題

現行の `_gen_visual()` は**シーンごとに独立してVeoを呼ぶ**。シーン5の生成はシーン4が何を
出したかを知らない。頼りは「マスコット画像1枚+文章」だけなので、**シーンの数だけキャラを
引き直している**。2026-07のコトラ版テストフィルムでカット間の別人化が起きた原因はこれ。

2026-08-03の検証で分かったのは、**一貫性は動画生成では担保できない**ということ。担保するのは
静止画の側で、動画生成には「承認済みの2枚の間を埋める」仕事しかさせない。

```
現行:  台本 → シーン割り → [シーンごとにVeoへプロンプト] → 動画
                              ↑ ここで毎回キャラを引き直す

本設計: 台本 → カット割り → 原画生成(鎖) → 【絵コンテGate】 → 中割り → 動画
                              ↑一貫性はここで確定    ↑人間が演出を握る  ↑埋めるだけ
```

## 2. 一貫性の鎖

原画は**単独生成しない。必ず前の絵から派生させる。**

```
正史立ち絵(docs/characters/)      ← 不変。再抽選しない
    ↓ 画像モデル(キャラを入力画像として渡す)
カットの原画A
    ↓ 画像モデル(原画Aを入力し「画角・背景・画風は維持、姿勢だけ変更」)
カットの原画B
```

原画Bを原画Aの編集で作る方式は 2026-08-03 に実証済み(顔・眼鏡・髪・服・背景・画風がすべて
維持された)。**この鎖を切らないことが設計の生命線**であり、原画をプロンプトだけから
単独生成する経路は作らない。

## 3. 状態機械の変更

既存の「台本確認待ち」と同じ形で、確認Gateを1つ追加する。

```
台本確認待ち ──承認──→ 絵コンテ作成中 ──生成完了──→ 絵コンテ確認待ち ──承認──→ 素材生成中 → …
                  │                                         │
                  └──(絵コンテ不要な案件はここから直接)──────┴──→ 素材生成中
```

追加する状態(`app/states.py`):

| 定数 | 表示 | 役割 |
|---|---|---|
| `STORYBOARD` | 絵コンテ作成中 | 原画A/Bを生成する工程 |
| `STORYBOARD_REVIEW` | 絵コンテ確認待ち | **人間が原画一覧を見て承認/差し戻す** |

- `TRANSITIONS` に上記を追加。`SCRIPT_REVIEW` の遷移先に `STORYBOARD` を足す
  (既存の `SCRIPT_REVIEW → ASSETS` は**残す**)
- `ROLLBACK_TARGETS` に `STORYBOARD` を追加(絵コンテからやり直せる)
- `ROLLBACK_SOURCES` に `STORYBOARD_REVIEW` を追加
- `_STAGE_ORDER` は `… SCRIPTING, STORYBOARD, ASSETS, EDITING, QA` の順に挿入
- `_ASSET_STAGE_OF` に `STORYBOARD: "storyboard"` を追加
  (差し戻し時に原画を `adopted=False` にできるようにする)

### 絵コンテ工程を通すかどうか

**必須にしない。** 通常の解説動画(止め絵+図解)には原画が不要で、必須化すると既存案件の
挙動が全部変わる。カットに1つでも中割りカットがある場合のみ絵コンテ工程へ入る。

## 4. データモデルの変更

`Scene` に追加(すべて既定値つき。**既存の保存済み案件はそのまま読める**):

```python
class Scene(BaseModel):
    ...
    # 絵コンテ駆動(docs/09)
    cast: list[str] = []         # このカットに映るキャラ。speaker(喋る人)とは別概念
    acting: str = ""             # 演技指示(日本語)「栞が顔を上げて手を振る」
    camera: str = ""             # カメラワーク "slow push-in" など
    keyframe_a_prompt: str = ""  # 原画Aの生成指示
    keyframe_b_prompt: str = ""  # 原画Bの生成指示(Aからの差分として書く)
```

`cast` と `speaker` を分けるのは、**画面に映ることと喋ることが一致しないため**。
ツヅリは映るが喋らない([07_キャラクター設定.md](07_キャラクター設定.md) の決定)。

`Scene.type` の語彙に **`genga_interp`** を追加する(`ai_video` / `still_motion` /
`diagram` / `text` に並ぶ第5の種別)。新しい分類軸を作らず既存の `type` を拡張する。

原画は既存の `Asset` にそのまま乗せる:

| stage | kind | scene_no | 内容 |
|---|---|---|---|
| `storyboard` | `keyframe_a` | カット番号 | 原画A |
| `storyboard` | `keyframe_b` | カット番号 | 原画B |

`find_asset(project, "storyboard", scene.no, "keyframe_a")` で引ける。版管理・差し戻し時の
`adopted=False` も既存の仕組みがそのまま効く。

## 5. キャラクター参照の解決

現行の `MASCOT_OBJECT`(単一パス)ではキャストを扱えない。設定を追加する:

```
CHARACTER_OBJECTS  {"栞": "config/character/shiori/v1.png",
                    "虎爺": "config/character/toraji/v1.png",
                    "ツヅリ": "config/character/tsuzuri/v1.png"}
```

そのカットに映るキャラは `Scene.cast` から引く(§4)。原画Aを生成するとき、
`cast` に挙がった全キャラの正史立ち絵を入力画像として渡す。

`MASCOT_OBJECT` は**削除しない**。旧経路(`ai_video`)は現状のまま動かす。

## 6. ツヅリの扱い

[07_キャラクター設定.md](07_キャラクター設定.md) の決定どおり、**ツヅリは生成対象から外す**。
原画にも中割りにも登場させず、完成した映像に対してスプライトとして合成する。
合成は既存のモーションエンジン(`motion.render_frames` と同じPIL→ffmpeg経路)に乗せる。

## 7. 費用と停止

絵コンテGateが**高額な動画生成の手前**に来ることが本設計の経済的な核心。

| 工程 | 課金 | 位置 |
|---|---|---|
| 原画A/B生成 | `imagen_image` × 2/カット | **Gateの前**(安い・捨てて撮り直せる) |
| 中割り | `veo_second` × 秒数 | **Gateの後**(承認済みの原画にしか使わない) |

- 原画生成・中割りとも `CostMeter.charge()` を経由する。今日判明した
  「パイプライン外の生成がコスト記録に残らない」穴は、この経路に乗せることで塞がる
- 絵コンテ工程で上限に当たった場合、動画に一円も使わずに停止できる

## 9. 決定事項(2026-08-03 豆虎回答)

1. **複数キャラ対応にする。** `Scene` に `cast: list[str]` を追加する。
   `speaker`(読み上げる話者)とは別概念として持つ — 画面に映ることと喋ることは一致しない
   (例: ツヅリは映るが喋らない)
2. **カット割りはGeminiにやらせる。** ショットリストをJSONで出させ、
   人間は絵コンテGateで承認する。人間が先に絵コンテを描く運用にはしない
3. **原画の差し戻し粒度 → 保留。§10の検証で決める**(どちらがキャラを保てるか不明のため)
4. **中割りの尺は可変。** カットごとに `Scene.duration_sec` を使う。
   現行の `AI_VIDEO_MAX_SEC = 8` を上限として維持する
5. **`reference_images` は要検証。§10で判定する**
6. **既存案件 `adc4e0d5ef95` は新経路に載せ替える。** 旧経路での完結はさせない。
   ただし載せ替えは本パイプラインが動いてからの作業とする

## 10. 実装前に必要な検証(V2)

3と5は仮説で決めると後で全部やり直しになるため、実測してから確定する。
**動画生成を伴うのは V2-C のみ**。V2-A / V2-B は静止画のみで安価。

### V2-A: 鎖の形(星型 vs 直列)

原画Aを各カットぶん作るとき、どこから派生させるか。

| 形 | 派生元 | 予想される性質 |
|---|---|---|
| **星型** | 各カットの原画A ← すべて正史立ち絵から直接 | 世代が1段。ドリフトが累積しない。カット単位の撮り直しが安全 |
| **直列** | カットNの原画A ← カットN-1の原画B | 隣接カットの連続性は出るが、世代を重ねるほど劣化が累積する |

同一キャラで3カットぶんの原画Aを両方式で生成し、正史との一致度を比較する。
**この結果がそのまま §9-3(差し戻し粒度)の答えになる** — 星型が勝てばカット単位で
撮り直せる(独立しているため)、直列が勝てば絵コンテ全体が1単位になる。

- 費用: `imagen_image` × 6

### V2-B: カット間の一貫性の実測方法

「崩れた」を主観で判定すると再現できない。正史立ち絵と各原画の差を機械的に測る手段を
先に用意する(候補: 顔領域の特徴量距離、色ヒストグラム距離、SSIM)。
**判定基準は検証の前に決めて記録する。結果を見てから基準を動かさない。**

- 費用: なし

### V2-C: `reference_images` の効果

原画Bを用意せず、`image`=原画A + `reference_images`=正史立ち絵 + プロンプトで
8秒生成し、A→B中割り(2026-08-03の実証)と比較する。

- **効けば**: 原画Bの生成が不要になり、1カットあたり `imagen_image` 1枚ぶん安くなる
- **効かなければ**: 原画の鎖だけで進める(現状の実証済み経路)
- 費用: `veo_second` × 8(`veo-3.1-lite`)

### 実施順

V2-B(基準づくり・無料)→ V2-A(静止画・安価)→ V2-C(動画)の順。
V2-A の結果が出た時点で §9-3 を確定し、本設計書に追記する(上書きはしない)。
