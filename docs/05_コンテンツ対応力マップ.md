# コンテンツ対応力マップ

- 作成日: 2026-07-22
- 目的: NEXDOCの方向性を決めるための、システム実力の正直な棚卸し
- 凡例: ◎=今日から量産可 / ○=無料の改修で到達 / △=作れるが強みが出ない / ×=構造的に不可

## ◎ 高適合(現状の実力で成立)

| ジャンル | 根拠 |
|---|---|
| 仕組み・構造の解説(技術/科学/宇宙/歴史/経済) | ナレーション+図解モーション+雰囲気映像が本来の設計 |
| 失敗事例・意思決定分析 | 8セクション構成(フック→転換点→教訓)の本来の姿 |
| 「なぜ〇〇は△△なのか」考察系 | 同上 |

## ○ 中適合(ジャンル別台本テンプレ等の追加で到達。費用ゼロ・数日)

| ジャンル | 必要な追加 |
|---|---|
| 比較・ランキング・「〇選」 | 列挙型の台本テンプレ(図解側は対応済み) |
| ハウツー・手順 | 手順型テンプレ(stepsモーションは実装済み) |
| データ・統計解説 | グラフ描画テンプレ(matplotlib/PIL) |
| 週次ニュースまとめ | まとめ型テンプレ+鮮度運用ルール(速報性依存はNGのまま) |
| マスコット(コトラ)進行番組 | Veo参照は実装済みだが品質未検証。口パク・セリフ同期は不可。「登場カット」が現実ライン |

## △ 低適合(作れるが強みなし)

- 朗読・怪談・物語系: TTSの感情が平板
- 対談・掛け合い: 複数話者TTSは追加可能だが「間」はAI台本の弱点

## × 構造的に不可能

| できないこと | 理由 |
|---|---|
| 実写素材前提(Vlog/実機レビュー/旅/料理) | 撮影素材が無い |
| ゲーム実況・画面録画 | キャプチャ無し+実UI模倣は禁止方針 |
| 歌・ボーカル曲 | Lyriaはインスト専用 |
| 長尺会話劇・精密なキャラ演技 | 要件3.3で除外。フェーズ3でもプリセット演技まで |
| 当日速報 | リードタイム+人間Gateと本質的に不整合 |
| 実在人物の再現映像 | 顔生成禁止ポリシー |
| 「間」で笑わせるエンタメ | AI台本の天井。人間の脚色が必須 |

## アニメーション表現の実力(4ティア)

| ティア | 内容 | 可否 | コスト |
|---|---|---|---|
| T1: 立ち絵+口パク | コトラ表情差分+音量同期の口パク+揺れ(ゆっくり解説系の定番構造)。「マスコットのストーリー調解説」の現実解 | ○ 拡張3〜5日 | 初回差分生成¥数十、以降毎本¥0 |
| T2: Veoアクセントカット | 8秒の動くカットを要所に(参照画像でキャラ固定) | ✅実装済(品質未検証) | ¥480/カット |
| T3: プリセット演技(Blender) | 頷く/指差す等+リップシンク(docs/04) | 📋設計済・GO待ち | 開発1〜2週、運用¥0 |
| T4: フルアニメ(自由演技・物語) | 精密制御が不可能(Veo=運任せ秒課金/Blender=プリセット限界) | × | — |

- T1の要検証点: 表情差分の一貫性(画像編集モードで生成、検証¥50程度)、背景切り抜き(OSSで可)
- 「ストーリー調アニメ解説」= T1常駐+T2アクセント+図解モーションの複合が現実ライン

## 注意書き(重要)

1. 「実装済み」≠「品質検証済み」。未検証: Veoマスコット参照の画質/動き、
   Lyria BGMの音楽性、長尺視聴時のTTS疲労感
2. システムが保証するのは工程・正確性・コストの管理。
   **「面白さ」は企画の切り口と台本推敲(人間の仕事)に依存する**
3. どのジャンルでも要件のガード(情報源記録・公平性・ロゴ/文字の生成禁止・
   人間Gate)は共通で効く
