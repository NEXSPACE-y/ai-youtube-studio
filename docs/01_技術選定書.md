# AI YouTube制作システム 技術選定書

- 作成日: 2026-07-21
- 対象: 要件定義書(本編)+ 要件追補案 + 追加決定事項
- 位置づけ: 要件書16章「範囲外」とされた設計判断のうち、技術選定を確定するもの

## 1. 確定済みの前提

| 項目 | 決定 |
|---|---|
| 実装言語 | Python |
| 提供形態 | Webアプリ(ブラウザから操作)。GCP上にホスティングし、外部SaaSは使用しない |
| 運用者 | 豆虎 1名(運用者兼最終承認者) |
| 配信ペース | 初期は週1本(月4〜5本)。収益化・安定運用を条件に段階増産 |
| エコシステム | Google/GCP限定。GCP上で動かすOSSは補助処理として許容(要件追補1章) |
| 公開フロー | 非公開/限定公開でアップロード → 豆虎Gate承認 → 公開 |

## 2. 全体アーキテクチャ

```
[ブラウザ(豆虎)]
      │ Google OAuth(本人のみ許可)
      ▼
[管理・承認Webアプリ]  Cloud Run (FastAPI + Jinja2/HTMX)
      │  案件作成・工程確認・承認・差し戻し を1画面系統で完結(追補4章)
      ▼
[Firestore] 案件状態・工程履歴・承認記録・コスト記録
      │
      ▼ ジョブ投入 (Cloud Tasks)
[生成パイプラインWorker]  Cloud Run Jobs (Python)
      ├─ Vertex AI Gemini ……… 企画・リサーチ・台本・投稿文面
      ├─ Vertex AI Veo ………… 要所のAI動画(コスト方針: 追補2章)
      ├─ Vertex AI Imagen …… 静止画・サムネイル素材
      ├─ Vertex AI Lyria ……… BGM
      ├─ Cloud Text-to-Speech … ナレーション
      ├─ Cloud Speech-to-Text … 字幕タイムスタンプ同期(追補7章)
      └─ ffmpeg (コンテナ内) … 合成・簡易モーション・書き出し
      │
      ▼
[Cloud Storage] 全成果物(案件ID/工程/シーン/バージョンで階層化: 要件8章)
      │
      ▼ 承認後のみ
[投稿サービス(分離)]  Cloud Run (別サービス・別サービスアカウント)
      └─ YouTube Data API v3 … 非公開アップロード / 公開操作
[YouTube Analytics API] → 分析画面(12章の指標を三分類で表示: 追補6章)
```

ポイント:
- **投稿サービスを生成パイプラインから物理分離**(要件9章「動画公開操作を他の生成処理から分離」)。YouTube権限を持つのはこのサービスだけ。公開APIは承認レコードがFirestoreに存在しないと実行を拒否する。
- 承認UIは1画面で「対象動画プレビュー・確認事項チェックリスト・情報源一覧・差し戻し先選択」を完結(追補4章の巡回禁止要件)。

## 3. 工程別サービスマッピング

| 工程(要件5章) | 使用サービス | 補足 |
|---|---|---|
| 5.1 企画作成 | Vertex AI Gemini | テーマ候補・タイトル案・重複チェック(過去案件をFirestoreから照合) |
| 5.2 リサーチ | Gemini + Google検索グラウンディング | 情報源URLを必ず構造化保存。事実/推測/創作のラベル付け必須。NotebookLMは手動深掘り用の補助 |
| 5.3 台本作成 | Gemini | ナレーション/画面表示/映像指示を分離したJSON構造で管理 |
| 5.4 映像構成 | Gemini | シーン分割・秒数割当・映像種別(AI動画/静止画+モーション/図解)の指定 |
| 5.5 素材生成(動画) | Vertex AI Veo | 冒頭フック・転換点など要所限定(追補2章)。案件別上限で停止制御 |
| 5.5 素材生成(画像) | Vertex AI Imagen | シーン背景・図解ベース・サムネイル |
| 5.5 素材生成(音声) | Cloud Text-to-Speech | 日本語高品質ボイス。固有名詞はSSML読み指定で制御(要件6.3) |
| 5.5 素材生成(BGM) | Vertex AI Lyria | 生成物の利用条件を案件単位で記録(11章のAI申告と連動) |
| 5.5 字幕 | 台本 + Cloud Speech-to-Text | 完成ナレーションをSTTにかけて単語タイムスタンプを取得し、台本テキストと突き合わせて同期(追補7章)。表示テキストは台本を正とする(STT誤認識の混入防止) |
| 5.6 動画編集 | ffmpeg on Cloud Run Jobs | 静止画パン/ズーム、クロスフェード、音量ダッキング(BGM自動減衰)、字幕焼き込み or SRT |
| 5.7 投稿準備 | Gemini | タイトル・概要欄・チャプター・タグ・AI申告文をドラフト生成 → 豆虎が編集可 |
| 5.8 公開承認 | 承認Webアプリ | チェックリスト形式。承認記録(承認者・日時・確認項目)をFirestoreに保存 |
| 7章 案件管理 | Firestore | 12状態のステートマシン + 差し戻し記録(追補5章) |
| 8章 保存 | Cloud Storage | `案件ID/工程/シーン番号/バージョン` の命名規則。メタデータはFirestore側に持つ |
| 9章 認証情報 | Secret Manager + サービスアカウント | コード埋め込み禁止。YouTube権限は投稿サービスのみ |
| 10章 コスト | Firestore(呼び出しメータリング) + Cloud Billing予算アラート | 生成API呼び出しごとに案件IDと概算費用を記録。上限超過予測で停止→承認要求 |
| 12章 分析 | YouTube Analytics API + 管理画面 | 自動取得/Studio目視/代替計測の三分類表示(追補6章) |

## 4. 料金の考え方(目安)

> ⚠️ 単価は変動するため、実数値は試験動画1本の実測(追補3章)で確定する。以下はオーダー感のみ。

- **支配的コストはVeo(AI動画生成)**。秒単価課金のため、1本あたりのAI動画使用秒数×再生成回数がほぼ費用を決める。追補2章の「要所限定」方針が効いている限り、週1本運用の月額は数千円〜1万円台のレンジに収まる想定。
- Gemini(テキスト)、Imagen(静止画)、TTS、Lyria、STTは合計しても1本あたり数百円オーダー。
- Cloud Run/Firestore/Cloud Storageは週1本規模では無料枠〜数百円。
- 案件別上限の初期値は仮置きし、試験動画の実測後に豆虎Gateで確定する。

## 5. セキュリティ設計方針(要件9章対応)

1. 認証情報はすべてSecret Manager。リポジトリ・ログ・生成プロンプトに含めない(ログ出力時のマスキング処理を共通化)。
2. Webアプリの認証はGoogle OAuthで豆虎のアカウントのみ許可リスト方式。
3. YouTube APIスコープは `youtube.upload` + 動画管理の最小限。投稿サービス専用のサービスアカウント/OAuthクライアントに限定。
4. 「公開」操作は承認レコード(承認者・日時・チェックリスト完了)の存在をサーバ側で検証してから実行。UIだけの制御にしない。
5. 生成パイプラインはYouTube権限を一切持たない。

## 6. 実装フェーズ計画

**フェーズ1: 試験動画1本を通す最小構成**(要件14章)
1. Firestoreの案件モデル + 状態管理
2. 企画→リサーチ→台本の生成パイプライン(Gemini)
3. 素材生成(Imagen/TTS/Veo最小限/Lyria)
4. ffmpeg合成 + 字幕同期
5. 承認画面(プレビュー + チェックリスト + 差し戻し)
6. YouTube非公開アップロード + 承認後公開
7. コスト・所要時間の計測レポート

**フェーズ2: 運用改善**(試験動画の豆虎Gate承認後)
- 承認UXの改善、Shorts切り出し、分析画面、失敗工程の自動リトライ

**フェーズ3: 増産対応**(収益化・安定運用の確認後)
- 並行案件処理、テンプレでない範囲での工程最適化
