# T4(フルアニメ表現)攻略の精密検討

- 作成日: 2026-07-22
- 結論: **「不可能」は言い過ぎだった。「リミテッドアニメーションの文法 × 原画主導パイプライン」
  で、インディーアニメ品質のストーリー調アニメは到達圏内。** ただし前提の転換が必要。

## 1. なぜT4を「不可能」としたか(再掲)

1. 制御性: 生成動画はプロンプトの運任せ。演技は指示できない
2. 一貫性: カット間でキャラの見た目が変わる
3. 経済性: ¥60/秒 × 分単位 = 破産
4. 口パク・セリフ同期が取れない

## 2. 前提の転換: アニメは「フルフレーム」ではない

TVアニメの実態は**リミテッドアニメーション**:
- 止め絵+カメラワーク(PAN/ZOOM)が大量にある
- 動くのはカットの中の一部の時間だけ
- 原画(キーフレーム)→中割り、という構造で「動き」を節約する

つまり**アニメの文法自体が「静止画多め+要所だけ動かす」**であり、
本システムの経済構造(静止画¥6/動画¥60秒)と本質的に噛み合う。
フルフレーム3DCG映画を目指すから不可能なのであって、
リミテッドの文法に乗るなら話が変わる。

## 3. 攻略の鍵(API実地確認済み 2026-07-22)

google-genai SDK 2.13.0 / Veo APIで以下を確認:

| 機能 | APIパラメータ | アニメ制作上の意味 |
|---|---|---|
| 始点フレーム指定 | `image` | **原画1枚目** |
| 終点フレーム指定 | `config.last_frame` | **原画2枚目 → Veoが中割りを生成** |
| キャラ・画風参照 | `config.reference_images`(image+reference_type) | カット間の一貫性 |
| カット延長 | `video`引数 | 8秒超の連続ショット |
| 再現性 | `seed` / `negative_prompt` / `fps` | ブレの抑制 |

**核心: 「原画→中割り」というアニメ制作の本工程が、そのままAPIで再現できる。**
原画は静止画生成(コトラ参照つき、¥6/枚)で作る。静止画は安い・何度でもやり直せる・
**人間Gateで事前確認できる**(=運任せの排除)。動きの生成は承認済みの原画2枚の
「間」に限定されるので、暴れる余地が構造的に小さい。

## 4. パイプライン設計「絵コンテ駆動」

```
台本 → カット割り(Gemini: shot list JSON)
        {"cut": 12, "type": "genga_interp", "duration": 6,
         "camera": "slow push-in", "acting": "コトラが振り返って驚く",
         "keyframe_a": "コトラ後ろ姿・夕暮れの丘", "keyframe_b": "コトラ振り返り驚き顔"}
  ↓
原画生成(画像モデル+コトラ参照) … ¥6/枚、失敗したら捨てて再生成
  ↓
【絵コンテGate】人間が原画一覧を見て承認/差し戻し ←★ここで演出を人間が握る
  ↓
カット製造(種別ごとに最適エンジン):
  - 止め絵+カメラワーク     … ¥0(既存zoompan/モーションエンジン)
  - 原画A→B中割り(Veo)      … ¥480/8秒カット
  - 参照+プロンプト(Veo)    … ¥480(自由演技が欲しい時だけ)
  - カット延長(video引数)   … 長回しが必要な時だけ
  ↓
組立(既存ffmpeg統合)+ 口パク重畳(T1エンジン)+ 字幕・テロップ・BGM
```

既存の管理・承認・コスト管理はそのまま流用(カット割り=シーンの拡張)。

| 止め絵カット(PAN/ZOOM) | 全体の6割 | 原画¥6×40枚 ≒ ¥240 |
| Veo中割りカット | 20カット(160秒分) | ¥9,600 |
| 音声・BGM・図解 | — | ¥50 |
| **合計** | | **約¥10,000/本** |

- Veo Fast系モデルが使えれば半額圏(要検証)
- 通常の解説動画(¥300〜1,300)とは別枠の「プレミアム動画」として月1本等の運用が現実的

## 6. Path 2: OSS動画モデル on GCP GPU(コスト1/10の道)

追補1章(GCP上のOSS可)の枠内で、オープン動画モデルを自前GPUで回す道:

- 候補: Wan系(Apache 2.0)、アニメ特化系(AniSora等)、中割り特化(ToonCrafter系)、
  ポーズ駆動(キャラ画像+モーション列→演技。演技プリセットの2D版)
- 経済性: L4/A100スポットで1本¥300〜1,000 → **量産可能圏**
- 代償: モデル運用の工数(2〜3週)+**ライセンス地雷**(要個別確認:
  ToonCrafter系は非商用条項、顔駆動系はInsightFace依存の非商用問題が典型)
- 位置づけ: Path 1で型を確立した後の「原価低減フェーズ」として検討

## 7. それでも残る限界(正直リスト)

- 京アニ/劇場品質の作画密度・複数キャラが絡む激しいアクション → 無理
- 完全なリップシンク → 近似まで(口パクはT1方式の重畳が現実解)
- カット内の演技の微調整(「0.3秒早く振り向く」) → 再生成ガチャになる
- 画風の完全固定 → 参照+seedで抑えられるが、カット間の微ブレは残る
- 原画の絵作り自体の品質 → 画像モデルの天井に従属(手・複雑なポーズは要リテイク)

到達点の正しい期待値: **「インディーアニメ/モーションコミックの上位」品質の
ストーリー調アニメ解説・短編**。これはYouTubeでは十分戦えるゾーン。

## 9. 実写風ホスト人物の肖像権ガード(2026-07-22追記・豆虎方針)

背景: 画風の著作権リスク(ピクサー風等の模倣)を避けるため、ホストは実写風の
架空人物を軸に検討。ただしネット上の「特定班」による拡大・照合を前提に設計する。

1. **生成時の除外指示**(一次フィルタ・効果は限定的):
   プロンプトに「実在の人物・著名人・公人に似せない。複数人の特徴を合成した
   一般的な顔立ちにする」を必須で含める
2. **顔類似チェックGate**(本体・豆虎の「類似許容度30%」案の実装形):
   生成後にOSS顔特徴量モデルで著名人顔データセットと照合し、
   最大類似度がしきい値超過なら自動リジェクト→再生成。
   結果は案件の承認記録に添付(監査証跡)。
   ※プロンプトで類似度は制御不能のため、必ず「生成後の検証」として実装する
   ※OSS顔認識モデルはライセンス要確認(非商用条項が多い領域)
3. **生成来歴の保存**: 生成プロンプト・日時・モデルを記録済み(既存機能)+
   Google画像生成のSynthID透かし = 「架空人物である」ことの証明手段
4. **正史顔の固定**: 検証を通過した1枚を正として参照生成し続ける。
   顔の再抽選をしない=類似リスクの再抽選もしない
5. 運用ルール: 顔アップで喋らせない(口パク回避と兼用)、実在の誰かへの
   類似を指摘されたら即時差し替えられるよう、ホスト依存を薄めた構成を保つ
